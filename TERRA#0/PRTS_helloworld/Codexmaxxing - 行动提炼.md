# Codexmaxxing - 行动提炼

> 关联页：[[Codexmaxxing - 内容总结]]  
> 目标：把视频里的 Codexmaxxing 方法转成可执行的个人工作流程。

## 可执行结论

Codexmaxxing 的落点是：把 Codex 用在可复用、可审阅、可持续推进的任务流程中。基本做法是“长期线程保存任务上下文、文件记录关键信息、人类持续纠偏、工具完成验证、自动化追踪后续”。

## 工作流程模板

### 1. 开始任务前

- 写清楚目标：这次任务要交付什么，什么状态算完成。
- 写清楚边界：哪些文件、工具、账号、环境可以用，哪些不要碰。
- 写清楚验收：要跑哪些测试、看哪些页面、生成哪些文件或报告。
- 把长期规则放进项目文件，例如 `AGENTS.md`、README、任务笔记或 Obsidian 页面。

### 2. 任务推进中

- 用长期线程处理跨天任务，例如 release、PR 反馈、文档整理、资料追踪。
- 用文件保存关键状态，例如当前决策、待办清单、阻塞点、验证结果。
- 中途用 steering 纠偏：发现方向不对时直接修正目标，不必重开上下文。
- 把粗糙想法先说出来，让 Codex 帮你整理成步骤、文件修改和检查项。

### 3. 任务完成前

- 要求 Codex 做最后验证：测试、截图、日志、链接、文件是否都符合目标。
- 要求它说明信息来源和限制，尤其是浏览网页、视频、外部文档时。
- 把可复用经验记录回文件：项目约定、问题、命令、检查清单。
- 对长期任务留下下一步，让之后的线程可以继续处理。

## 推荐的 Obsidian 结构

### 项目主页

- 项目目标
- 当前状态
- 关键链接
- 环境命令
- 验收标准
- 重要决策
- 后续待办

### Codex 协作页

- 常用 prompt
- 项目禁区
- 已知问题
- 测试方式
- 发布流程
- 需要人工确认的事项

### 任务页

- 本次目标
- 输入材料
- 执行过程
- 产出文件
- 验证记录
- 复盘结论

## 重点清单

- 把 Codex 当“持续协作者”，不要只当“代码补全器”。
- 把知识写进文件，避免上下文只存在聊天里。
- 长任务用 durable thread，短问题用临时线程。
- 用 Voice 或粗略输入降低启动成本，再通过中途纠偏提高质量。
- 用浏览器、文档、表格、MCP、connectors 扩展任务边界。
- 用侧边栏和预览减少从生成结果到审阅结果的等待时间。
- 用 Heartbeats 和 Goals 追踪明确任务，不要自动化模糊目标。
- 每次完成后记录检查清单，下一次让 Codex 基于更完整的上下文开始。

## 我的实践建议

### 最小可行做法

先建立三个文件：

- `AGENTS.md`：写项目规则、测试命令、不要触碰的区域。
- `TODO.md`：写当前任务、下一步、阻塞点。
- `WORKLOG.md`：写每次 Codex 做了什么、验证了什么、还剩什么。

### 进阶做法

- 每个重要项目开一个长期线程，避免反复解释背景。
- 每次让 Codex 改完东西后，要求它把“可复用经验”写回项目笔记。
- 对经常重复的检查建立 checklist，例如 PR 检查、文档发布、视频总结、资料归档。
- 对外部等待型任务使用 heartbeat，例如“明天检查 PR 评论”“每小时看一次 CI”“下周复盘资料更新”。

## 可以直接复制的提示词

```text
你现在是这个项目的长期协作者。先阅读 AGENTS.md、TODO.md 和最近的工作记录，再继续推进当前任务。推进时请保持以下习惯：先确认目标和验收标准，再修改文件；修改后运行必要验证；最后把关键结论、剩余问题和下一步写回项目笔记。
```

```text
请把这次工作整理成 Obsidian 笔记：包括目标、输入材料、关键决策、执行步骤、验证结果、未解决问题和下一步。内容要让未来的我或未来的 Codex 可以直接接着做。
```
