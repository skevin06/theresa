# TLS 握手过程

## P0 视频范围

**时间轴：06:30-11:30**

本文件对应技术蛋老师视频《HTTPS是什么？加密原理和证书。SSL/TLS握手过程》中后半段的 TLS 握手讲解。视频没有讲 TCP 四次挥手；这里的“握手”是 HTTPS 里的 **TLS 握手**。

## P0 总流程

**时间轴：06:30-07:00**

作者先说明：HTTP 默认 80 端口，HTTPS 默认 443 端口；不同 TLS 版本和加密套件名称不完全一样，因此双方要先协商。

```text
TCP 三次握手
→ TLS 握手协商版本、加密套件、证书和密钥材料
→ 生成会话密钥
→ 用会话密钥加密传输 Application Data
```

## P1 抓包视角

**时间轴：07:00-09:15**

视频用抓包软件展示 HTTPS 连接中的 TLS 消息。作者强调先看 `Client Hello`，其中能看到客户端支持的 TLS 版本、加密套件组合和随机数；之后服务端回复 `Server Hello`，选出后续要使用的版本与套件。

| 时间轴 | 抓包中看的消息 | 作者讲解重点 |
|---|---|---|
| 07:00-07:30 | `Client Hello` | 客户端先发自己支持的 TLS 能力 |
| 07:30-08:00 | `Server Hello` | 服务端返回它选中的版本、套件和随机数 |
| 08:00-08:45 | `Server Key Exchange` 等 | 服务端下发密钥交换相关参数 |
| 08:45-09:15 | `Client Key Exchange`、`Change Cipher Spec`、握手消息 | 客户端确认并开始进入加密通信阶段 |

## P1 握手总结图

**时间轴：09:30-11:30**

| 步骤 | 方向 | 视频画面中的消息 | 作用 |
|---|---|---|---|
| 1 | 客户端 → 服务端 | `Client Hello`：TLS 版本、加密套件、第 1 随机数 | 客户端报出自己支持什么 |
| 2 | 服务端 → 客户端 | `Server Hello`：TLS 版本、加密套件、第 2 随机数 | 服务端选择双方都能用的方案 |
| 3 | 服务端 → 客户端 | `Certificate` | 发送证书，让客户端确认服务器身份，并拿到公钥 |
| 4 | 服务端 → 客户端 | `Server Key Exchange` | 发送密钥交换相关信息 |
| 5 | 服务端 → 客户端 | `Server Hello Done` | 服务端这一轮消息结束 |
| 6 | 客户端 → 服务端 | `Client Key Exchange`、`Change Cipher Spec`、`Encrypted Handshake Message` | 客户端用公钥加密预主密钥/第 3 随机数，并切换到加密通信 |
| 7 | 服务端 → 客户端 | `Encrypted Handshake Message` | 服务端确认双方计算出的会话密钥一致 |
| 8 | 双向 | `Application Data` | 后续业务数据使用会话密钥加密传输 |

## P1 密钥生成逻辑

**时间轴：10:00-10:45**

视频总结图里把密钥材料拆成三部分：

```text
第 1 随机数
+ 第 2 随机数
+ 预主密钥 / 第 3 随机数
= 会话密钥
```

客户端用服务器证书里的公钥加密预主密钥后发给服务端；服务端用自己的私钥解开。这样双方都能得到同一份会话密钥，后面的数据就用对称加密方式传输。

## 易错点

- TCP 三次握手和 TLS 握手不是同一层：TCP 先建立连接，TLS 再协商加密。
- TLS 握手的目的不是直接传网页内容，而是协商出后续加密传输用的会话密钥。
- 证书不只是“加密用文件”，还承担服务器身份认证和公钥分发作用。
