# HTTPS 视频中的 TCP 三次握手

## P0 作用

**时间轴：06:30-07:00**

技术蛋老师在讲 HTTPS/TLS 前先强调：**正常的 TCP 三次握手是不变的**。也就是说，HTTPS 不是跳过 TCP 直接加密通信，而是先让浏览器和服务器建立 TCP 连接，然后再进入 TLS 握手。

## P1 三次握手步骤

| 次数  | 发送方 | 报文/字段                                         | 状态变化                         |
| --- | --- | --------------------------------------------- | ---------------------------- |
| 第一次 | 客户端 | 发送 `SYN` 包，`syn=j`                            | 客户端进入 `SYN_SEND`，等待服务器确认     |
| 第二次 | 服务端 | 确认 `ack=j+1`，并发送自己的 `SYN`，`syn=k`，即 `SYN+ACK` | 服务端进入 `SYN_RECV`             |
| 第三次 | 客户端 | 收到 `SYN+ACK` 后发送确认包 `ACK(ack=k+1)`            | 客户端和服务端进入 `ESTABLISHED`，连接建立 |

## P1 在 HTTPS 流程里的位置

**时间轴：06:30-07:15**

```text
访问 HTTPS 站点
→ 目标端口从 HTTP 的 80 变为 HTTPS 的 443
→ TCP 三次握手：SYN / SYN+ACK / ACK
→ 开始 TLS 握手：协商 TLS 版本、加密套件和密钥材料
```

作者这里的重点不是重新讲 TCP 状态机，而是说明：**HTTPS 的安全性来自后面的 TLS 握手和加密，不是 TCP 三次握手本身发生了变化**。

## 易错点

- 三次握手不是传业务数据的主要过程，而是建立 TCP 连接的确认过程。
- 不要把 TCP 三次握手和 TLS 握手混成一件事；前者建立连接，后者协商加密通信。
- HTTPS 使用 443 端口和 TLS 加密，但底层仍先经过 TCP 三次握手。
