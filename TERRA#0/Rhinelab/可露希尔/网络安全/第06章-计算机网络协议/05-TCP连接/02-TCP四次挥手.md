# TCP 四次挥手

## 源校验

用户指定的新视频 `BV1KY411x7Jp` 讲的是 HTTPS、证书和 TLS 握手过程；它没有讲 TCP 四次挥手。若这里说的“四次握手”是指 HTTPS 里的 TLS 握手，请看：[[04-HTTP与HTTPS/04-TLS握手过程]]。

## P0 作用

**时间轴：21:00-23:30；29:00-29:10 画面回看**

建立 TCP 连接需要三次握手，终止 TCP 连接需要四次挥手。作者继续使用客户端/服务端对话图说明连接释放。

## P1 四次挥手步骤

| 次数 | 发送方 | 报文/字段 | 状态变化 |
|---|---|---|---|
| 第一次 | 客户端 | 发送连接释放报文，`FIN=1`，序列号 `seq=u` | 客户端进入 `FIN-WAIT-1` |
| 第二次 | 服务端 | 收到后发确认，`ACK=1`，`ack=u+1`，带自己的序列号 `seq=v` | 服务端进入 `CLOSE-WAIT` |
| 第三次 | 服务端 | 最后数据发送完后，向客户端发送连接释放报文 | 服务端进入 `LAST-ACK` |
| 第四次 | 客户端 | 收到释放报文后确认，`ACK=1`，`ack=w+1`，`seq=u+1` | 客户端进入 `TIME-WAIT`，之后进入 `CLOSED`；服务端收到确认后进入 `CLOSED` |

视频画面还提到：客户端在 `TIME-WAIT` 中等待，若 2MSL 后没有收到服务端重传报文，才进入 `CLOSED`。

## P2 视频图例

图中把四次挥手画成断开连接的对话：

```text
客户端：我要断开连接了
服务端：好的，我知道了
服务端：再来消息我就断了
客户端：好的，你断了吧
```

## 易错点

- 三次握手建立连接，四次挥手释放连接；不要把数量混在一起。
- 断开连接要考虑双方是否都已经没有数据要发，所以比建立连接多一步。
- `TIME-WAIT` 不是错误状态，而是等待可能的重传和保证连接彻底关闭。
