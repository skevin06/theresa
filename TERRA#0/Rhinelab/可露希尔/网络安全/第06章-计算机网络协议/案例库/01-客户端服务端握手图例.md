# 客户端服务端握手图例

## P2 作者为什么举这个例子

**时间轴：18:30-23:30；29:00-29:10 画面回看**

TCP 的 `SYN`、`ACK`、`FIN` 字段比较抽象，作者用客户端、手机消息气泡和服务端的图，把连接建立与释放转成日常对话。

## 对应哪个操作

| 视频图例 | 对应网络过程 |
|---|---|
| “你好！能收到吗” | 客户端发送 `SYN`，尝试建立连接 |
| “可以！你能收到吗” | 服务端返回 `SYN+ACK` |
| “OK！我也能收到” | 客户端返回 `ACK`，连接建立 |
| “我要断开连接了” | 客户端发送 `FIN` |
| “好的，我知道了” | 服务端确认 `ACK` |
| “再来消息我就断了” | 服务端数据处理完后发送 `FIN` |
| “好的，你断了吧” | 客户端确认，连接关闭进入收尾状态 |

## 物理 / 网络意义

三次握手解决的是“双方收发能力都确认”的问题；四次挥手解决的是“双方都确认不再发送数据并关闭连接”的问题。

## 容易错在哪里

- 把 `SYN+ACK` 看成两个独立阶段，导致三次握手被记成四次。
- 忽略服务端可能还有数据没发完，因此不理解为什么关闭连接要四次。
- 把图里的口语对话当成真实报文内容；真实传输看的是 TCP 字段和状态。
